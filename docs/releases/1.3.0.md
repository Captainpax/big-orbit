# Big Orbit 1.3.0

Status: exact signed candidate verified; Little Orbit production migration and publication in progress

Big Orbit now shares Little Orbit's 1.3.0 release-train label while retaining its independent package, version code, signer, and release artifact. The exact candidate is package `com.littleorbit.bigorbit`, version 1.3.0, code 3, 2,485,190 bytes, SHA-256 `deccc454920c08793b3ce56b570b5c049343a48a7008984d7de0f91713ea8a5b`, and pinned certificate SHA-256 `04dc3502933faaa99dfd6641acc52b2bd71c9895087cb3060e3ce92dd8406f8c`.

Fresh devices no longer need a pre-existing MFA proof to begin enrollment. The trusted Little Orbit console generates one eight-digit PIN, stored only as a hash and valid for ten minutes or five attempts. Password and PIN create a restricted resumable setup capability; a purpose-separated challenge proves the new Android Keystore key. The first owner then scans a protected TOTP QR and confirms one code. Later devices preserve existing MFA and proceed to ordinary device-bound sessions after key proof.

The observatory displays only content-free Little Orbit 1.3 health: weekly schedule, reviewed knowledge count, public-context freshness, one-use reserve capacity, weekly theme labels, and run outcomes. A regenerate action selects only the fixed next-week job. It accepts no command, SQL, path, URL, prompt, model argument, or relationship content.

The exact minified code-3 APK passes signer/package/version/hash inspection, excludes checked QA material, and fresh-installs and cold-launches on API 36 without a matching fatal exception or ANR. The published stable release remains Big Orbit 1.0.0 code 2 until Little Orbit 1.3 production compatibility and immutable publication complete. At the owner's request, physical cold launch, fresh/returning enrollment, malformed-response recovery, large text, alert polling, and revocation remain deferred live QA rather than passed evidence. A failed candidate is discarded without reusing its code or bytes.
